# 模块交互契约

本文定义跨模块接口、消息与状态归属，供实现使用。业务语义以[核心循环与角色职责说明](核心循环与角色职责说明.md)为准，编码与验证要求见[开发规范](开发规范.md)，实际实现范围见 [README](../README.md)。接口与消息类型已按 README 所述范围实现，运行编排能力仍以 README 为准；不能把设计约定直接当作现有代码能力。

## 1. 模块边界

| 模块 | 状态归属 | 对外职责 |
| --- | --- | --- |
| `domain` | 不持有运行状态 | 定义跨模块消息与身份类型，不依赖 Concordia |
| `roles` | 私有认知、意向与内部思考状态 | 实现角色交互接口，返回完整主动行为声明，内部编排 System1/2/3 |
| `world` | 客观事实、实际行动进展、被动影响与环境过程 | 检查声明、裁决实际结果，提交经运行时校验的事实，生成可获得的感知与反馈 |
| `engine` | 剧情时钟、事件队列、已接受的主动行为声明及行动登记记录 | 协调调用、等待全部角色、校验与统一登记，不决定角色意向或剧情结果 |
| `translator` | 当前翻译请求所需的上下文 | 将通过检查的主动尝试转为时间安排，保留提交组，不直接登记或提交事实 |
| `integrations/concordia` | 框架适配、模型调用记录与调试运行状态 | 接入组件、日志、回放、运行控制和真实界面步数据，不替代项目调度语义 |

引擎的行动记录负责身份、登记阶段和待处理节点；World 维护行动实际进展及作用。两者通过明确的结果同步。角色撤回主动行为时，不得删除 World 中的被动过程、已发生效果或其他角色的行动。

## 2. 角色实现主要交互接口

角色与世界主要通过角色实现的交互接口交互。用 Rust trait 表达如下：

```rust
trait RoleInteraction {
    fn role_id(&self) -> RoleId;

    // 接收本轮输入，返回从现在起要主动实施或维持的完整行为集合。
    async fn perceive(&mut self, input: TurnInput) -> RoleResponse;

    // 接收 World 的打回反馈，重新决定并返回完整行为集合。
    async fn rejected(&mut self, feedback: Rejection) -> RoleResponse;
}
```

Python 中扩展现有 `Role` 抽象基类表达该契约，方法使用 `async def`，不另加一层角色包装。类型名表示消息职责，具体字段按下表实现。

### `perceive`

- 输入投递前，本轮事件的客观结果已提交，信息已按本角色的范围过滤。
- 输入属于一个处理周期和剧情时刻，可包含多个同刻事件的感知，也可没有外部感知。
- 周期性内思考通过触发原因表达，不伪造外部感知；与外部事件同刻时合并为一次输入。
- 角色自行编排 System1/2/3。即使没有新决定，也须返回要继续主动维持的集合，不能用空集合表示未执行某个内部阶段。
- 方法可以更新自身私有状态，不写入 World、调度队列或剧情时钟。

### `rejected`

- 只接收针对本角色、当前周期、当前待检查响应的反馈。
- 角色根据原因调整做法、放弃尝试或重新考虑意向；外部不直接调用 System3，也不指定内部阶段。
- 返回新的完整声明，替代尚未接受的旧候选，不由外部合并增量。
- 没有新事件落地时，不重复投递原始感知；检查打回不是剧情中的执行失败。

World 产生检查反馈，由引擎协调投递到角色接口。World 检查中不递归调用角色。同一角色的交互调用必须串行，不同角色可以并行；完成先后不产生剧情优先级。

## 3. 消息与身份

跨模块消息使用明确类型和不可变结构；自然语言表达行动语义，身份、归属、时间和关联关系使用结构字段。

| 消息 | 必须表达的内容 |
| --- | --- |
| `TurnInput` | 本轮身份、角色身份、当前剧情时刻、触发原因、可获得的感知、自身可获知的行动状态及结果反馈 |
| `RoleResponse` | 本轮身份、角色身份、响应身份、完整主动行为集合 |
| 集合中的行动 | 稳定行动身份、主动尝试的描述；修改原行动时明确变化，本次新行动保留提交组关联 |
| `Rejection` | 本轮及角色身份、被打回的响应身份、有关行动身份、允许角色获知的原因 |
| `ActionCheckResult` | 被检查的响应、所依据的共同世界状态、通过或不通过及原因 |
| 翻译结果 | 原响应及提交组关联，各行动的开始与预计结束时刻、必要过程节点 |
| World 裁决结果 | 关联事件与行动、事实变更候选、实际状态变化、必要的后续世界事件；经校验提交后才能发布 |

`RoleResponse` 只有一份完整主动行为集合，不拆成 `new_group` 与 `action_updates` 两个独立输出。不要求角色声明被动过程，也不要求暴露完整私有认知。

每次响应可单独定位，打回反馈不得误用到另一轮或更新后的响应。已登记行动保持稳定身份；同 ID 的维持声明保留原进展与时间安排，不重新开始、重复登记或延长预计结束时间。确需修改时须明确变化，检查通过后才调整未来部分，不能改写历史。已完成行动不能靠重复旧 ID 重新启动。

提交组关联必须跨检查、翻译和登记保留。全量集合中的既有行动不重新组成新组；本次所有新行动组成一个并行组，按核心文档校验共同非零时间交集。

## 4. World 检查与事实提交

World 提供检查完整主动行为声明的入口，概念签名为：

```text
check_response(当前共同世界状态, 完整角色响应) -> ActionCheckResult
```

检查覆盖行为含义、当前步骤边界、未确认结果依赖、客观条件及与已有行动的关系，不只检查新增项。World 不替角色改目标、拆组或选择其他自主行为。模型可承担语义判断，运行时负责结构和一致性检查，不要求穷举所有情境的规则表。

本轮检查基于事件落地后的共同客观状态，不因角色完成先后改变事实前提。检查不开始行动、不提前提交停止效果、不预占对象、不登记事件。不同角色的候选独立检查通过，不保证未来互不影响，实际同刻事件仍须联合裁决。

角色是否继续愿意主动维持由角色决定。撤回维持后的身体运动、惯性、外力及其他效果由 World 判断；不能因为被动效果仍在持续，就要求角色把它声明为主动行为。具体业务例子见核心文档「全量主动行为声明与被动影响」。

World 在事件时刻先更新相关过程的实际进展，再基于共同状态裁决互相影响的事件。模型候选、运行时校验、实际提交和发布分开记录；未提交结果不得进入角色感知，提交错误不得留下半提交事实或发布成功结果。

## 5. 本轮流程与生效边界

```text
本轮事件落地，生成各角色输入
    ↓
角色 perceive → 完整主动行为声明 → World 检查
    ├─ 不通过：角色 rejected → 新完整声明 → 再检查
    └─ 通过：保存本轮候选，等待其他角色完成
    ↓
全部角色完成响应及必要的打回处理
    ↓
翻译、校验时间安排、统一登记与提交，新声明生效
    ↓
完成本轮，允许推进下一剧情时刻
```

新的全量声明经检查、完成本轮统一登记后替换此前已接受的声明。打回候选不提前撤回原声明或清空队列。撤回主动维持的实际作用仍经 World 裁决与校验提交，不能直接拿响应集合覆盖客观状态。

保持原状也须返回维持集合；合法空集合表示角色从现在起没有要主动实施或维持的行为。字段缺失、解析失败、调用尚未完成或运行错误，不得被转换为空集合。

新行动的时间安排须满足开始时刻晚于当前时刻、结束晚于开始及组内共同非零交集。时间校验失败不得悄悄拆组或登记部分行动；需要角色改变行为安排时，通过打回接口让角色重新决定。

引擎不逐阶段调用 System1/2/3。全部角色完成思考、检查、打回、翻译和登记前，整个周期及所有模块的模型调用均保持剧情时间冻结。先通过检查的角色不能先行动。

## 6. 实现约定与验证

- 剧情时间和时长统一使用非负整数毫秒；配置中的秒在入口转换，不由场景自行解释 tick，也不使用浮点值比较事件时刻。毫秒是存储分辨率，不表示每毫秒调用模型；调度仍跳转到最近事件。
- 结构校验覆盖类型、身份、归属、引用、时间与状态一致性。语义检查不通过走打回流程；模型超时、格式错误及程序异常属于运行错误，停止推进、保存现场，不代替角色作出空集合决定。
- 角色方法可能已更新私有状态，异常后不能盲目重放整个调用，不承诺整轮自动回滚。
- 感知、响应、检查、打回、翻译和登记记录本轮、角色、响应及适用的行动身份，能够沿因果链查找。Concordia 日志、运行控制和真实界面步数据随闭环功能交付，要求见开发规范。
- 使用假模型验证：维持不重启；遗漏只撤回主动维持；空集合不抹除被动影响；打回候选不生效；修改不改历史；新组关联不丢失；旧反馈不误用；重试不推进剧情时间；全部角色完成前不越过屏障；返回顺序不决定冲突结果。
