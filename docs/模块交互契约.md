# 模块交互契约

本文定义跨模块接口、消息与状态归属，供实现使用。业务语义以[核心循环与角色职责说明](核心循环与角色职责说明.md)为准，编码与验证要求见[开发规范](开发规范.md)，实际实现范围见 [README](../README.md)。接口、消息和模型驱动的 System1/2/3 已按 README 所述范围实现；模型驱动的翻译器与具体世界事实模型仍以可注入接口承接，不能把设计约定直接当作现有代码能力。

## 1. 模块边界

| 模块 | 状态归属 | 对外职责 |
| --- | --- | --- |
| `domain` | 不持有运行状态 | 定义跨模块消息与身份类型，不依赖 Concordia |
| `config` | 不持有运行状态 | 严格文件配置加载（`load_run_config`/`load_assembly_config`），秒在加载时验证整毫秒，不创建任务/模型/网络 |
| `app` | 装配过程状态 | 统一装配（live/scripted/replay，作用域命名空间 `role:`/`translator:`/`world:`）、运行编排、输出管理与错误快照导出 |
| `roles` | 私有认知、意向与内部思考状态 | 实现角色交互接口，返回完整主动行为声明，内部编排 System1/2/3 |
| `world` | 客观事实、实际行动进展、被动影响与环境过程 | 按流逝剧情时间更新进展，检查声明、裁决实际结果，提交经运行时校验的事实，生成可获得的感知与反馈 |
| `engine` | 剧情时钟、事件队列、已接受的主动行为声明及行动登记记录 | 协调调用、等待全部角色、校验与统一登记，不决定角色意向或剧情结果 |
| `translator` | 当前翻译请求所需的上下文 | 将通过检查的主动尝试转为时间安排（新行动组与修改的未来安排），保留提交组，不直接登记或提交事实 |
| `integrations/concordia` | 框架适配、模型调用记录与调试运行状态 | 接入组件、日志、回放、运行控制和真实界面步数据，不替代项目调度语义 |

引擎的行动记录负责身份、登记阶段和待处理节点；World 维护行动实际进展及作用。两者通过明确的结果同步（World 提交的结算结果更新登记阶段）。角色撤回主动行为时，不得删除 World 中的被动过程、已发生效果或其他角色的行动。

## 2. 角色实现主要交互接口

角色与世界主要通过角色实现的交互接口交互。用 Rust trait 表达如下：

```rust
trait RoleInteraction {
    fn role_id(&self) -> RoleId;

    // 接收本轮输入，返回从现在起要主动实施或维持的完整行为集合。
    async fn perceive(&mut self, input: TurnInput) -> RoleResponse;

    // 接收 World 的打回反馈，重新决定并返回完整行为集合。
    async fn rejected(&mut self, feedback: Rejection) -> RoleResponse;
}
```

Python 中扩展现有 `Role` 抽象基类表达该契约，方法使用 `async def`，不另加一层角色包装。类型名表示消息职责，具体字段按下表实现。

### `perceive`

- 输入投递前，本轮事件的客观结果已提交，信息已按本角色的范围过滤。
- 输入属于一个处理周期和剧情时刻，可包含多个同刻事件的感知，也可没有外部感知。
- 周期性内思考通过触发原因表达，不伪造外部感知；与外部事件同刻时合并为一次输入。
- 角色自行编排 System1/2/3。即使没有新决定，也须返回要继续主动维持的集合，不能用空集合表示未执行某个内部阶段。
- 方法可以更新自身私有状态，不写入 World、调度队列或剧情时钟。

### `rejected`

- 只接收针对本角色、当前周期、当前待检查响应的反馈。
- 角色根据原因调整做法、放弃尝试或重新考虑意向；外部不直接调用 System3，也不指定内部阶段。
- 返回新的完整声明，替代尚未接受的旧候选，不由外部合并增量。
- 没有新事件落地时，不重复投递原始感知；检查打回不是剧情中的执行失败。

System1/2/3 在角色内部实现（`roles/components/`）：组件经可注入的采样器协议调用模型，同角色串行（跨角色并行）；候选新行动与待生效修改在引擎确认前不进入可维持集合，打回候选不影响既有安排。阶段留痕（提示、原始模型输出、解析结果、跳过/重试/错误及预先分配并贯穿的周期/角色/响应/行动/剧情时间身份）写入与引擎相同的追踪链，追踪失败不掩盖模型/解析异常；模型 JSON 输出先经严格校验（类型/必填/未知字段/重复键/非有限常量/矛盾标记/引用冲突），省略集合、无法解析或冲突不得转换为空声明。Concordia 语言模型的异步桥、真实组件日志与按角色作用域隔离的录制/重放在 `integrations/concordia/sampling.py`（线程中的同步调用无法硬取消，取消只放弃等待）；领域模块不依赖框架。

World 产生检查反馈，由引擎协调投递到角色接口。World 检查中不递归调用角色。同一角色的交互调用必须串行，不同角色可以并行；完成先后不产生剧情优先级。

## 3. 消息与身份

跨模块消息使用明确类型和不可变结构；自然语言表达行动语义，身份、归属、时间和关联关系使用结构字段。

| 消息 | 必须表达的内容 |
| --- | --- |
| `TurnInput` | 本轮身份、角色身份、当前剧情时刻、触发原因、可获得的感知、自身可获知的行动状态及结果反馈 |
| `RoleResponse` | 本轮身份、角色身份、响应身份、完整主动行为集合 |
| 集合中的行动 | 稳定行动身份、主动尝试的描述；修改原行动时明确变化，本次新行动保留提交组关联 |
| `Rejection` | 本轮及角色身份、被打回的响应身份、有关行动身份、允许角色获知的原因 |
| `ActionCheckResult` | 被检查的响应、所依据的共同世界状态、通过或不通过及原因 |
| 翻译请求 | 原响应及提交组关联、当前时刻与共同状态版本、既有行动安排，以及 World 提供的只读客观上下文（共同版本与位置/姿态/障碍/实际进展条件，不进入角色感知；主观意向与客观条件在提示中区分） |
| 翻译器输出 schema | `schedules` 与 `modified_schedules` 各一次，一一对应本次新行动与明确修改（身份/提交组一致，整数毫秒）；维持不重译、无额外行动 |
| 翻译结果 | 原响应及提交组关联，各行动的开始与预计结束时刻、必要过程节点；修改声明给出修改后的完整未来安排 |
| World 裁决结果 | 关联事件与行动、事实变更候选、行动结算结果（开始/进行中/完成/失败/未确认）、必要的后续世界事件；经校验提交后才能发布 |
| 修改裁决输入 | 执行角色、原行动描述、明确变化与新旧未来安排；与统一登记一起生效 |
| 进展更新报告 | 周期与时刻、被更新的行动身份及说明；只依赖流逝的剧情时间，实际变化原子应用并递增版本 |
| World 诊断快照 | 只读的实际行动状态与被动过程，与事实增量文本分开；供界面与调试，不进入角色感知 |
| 场景事实模型 | 不可变对象树（身份/名称/类别/坐标/状态/容纳关系），场景卡加载严格校验；变更只能是结构化补丁（set_state/move/set_position）经候选校验提交后原子应用 |
| World 模型输出 schema | 检查 `{passed, reason, action_ids}`；进展 `{movements, updated_action_ids, notes, passive_updates}`（可选 `changes` 结构补丁与 `action_progress` 实际进展，不提前改变行动终态）；联合裁决 `{changes, outcomes, follow_ups, movements, stop_movements, passives, stop_passives}`——严格 JSON，列出的顶层数组字段必填（新增可选字段按 schema 明示），未知/重复字段与非有限数值、引用不一致是运行错误 |
| 可见性策略 | 默认关闭容器（state.open=false）隐藏全部后代，可注入语义策略；发布由已提交结构与提交后快照确定性生成（不广播模型自由描述），隐藏对象不进入任何角色侧模型提示，打开后新可见内容随发布传递 |
| 候选身份 | World 以对象身份（is）核对生成现场：值相等伪造、重复提交、过期版本/基线、写入期在途检查全部整批拒绝；合法无变化事件允许提交并严格递增版本 |

`RoleResponse` 只有一份完整主动行为集合，不拆成 `new_group` 与 `action_updates` 两个独立输出。不要求角色声明被动过程，也不要求暴露完整私有认知。

每次响应可单独定位，打回反馈不得误用到另一轮或更新后的响应。已登记行动保持稳定身份；同 ID 的维持声明保留原进展与时间安排，不重新开始、重复登记或延长预计结束时间。确需修改时须明确变化，检查通过后调整未来部分并经 World 结构化裁决实际生效（输入携带执行角色、原描述、明确变化与新旧未来安排），不能改写历史（已开始的开始时刻与已过的过程节点不可改写；修改后的结束必须晚于当前时刻）。已完成、失败或已撤回的行动不能靠重复旧 ID 重新启动或重新维持；未确认表示结果未知而非已知终止，后续节点与主动维持不凭未知删除。

提交组关联必须跨检查、翻译和登记保留。全量集合中的既有行动不重新组成新组；本次所有新行动组成一个并行组，按核心文档校验共同非零时间交集。修改声明不参与新组交集约束。

## 4. World 检查与事实提交

World 提供检查完整主动行为声明的入口，概念签名为：

```text
check_response(当前共同世界状态, 完整角色响应, 只读既有安排) -> ActionCheckResult
```

检查输入还携带该角色由引擎提供的只读既有安排快照（`ActionArrangement` 元组，可为空，兼容独立新声明的检查入口），供判断维持/修改与既有安排的关系。安排属于引擎并可能包含尚未实际开始的登记等待行动；World 不写入或缓存为已登记事实、不把登记当作实际开始、不使安排进入角色感知，维持等待中的行动仍按可见场景检查客观条件。

检查覆盖行为含义、当前步骤边界、未确认结果依赖、客观条件及与已有行动的关系，不只检查新增项。World 不替角色改目标、拆组或选择其他自主行为。模型可承担语义判断，运行时负责结构和一致性检查，不要求穷举所有情境的规则表。

时钟进入事件时刻后、同刻裁决之前，World 按已流逝的剧情时间更新相关未完成行动与被动过程的实际进展（`update_progress`）；进展只由剧情时间与 World 判定决定，实际变化原子应用并递增共同状态版本。随后引擎把同刻整批事件交给 World 联合裁决：`adjudicate` 收到完整事件内容与行动节点（事件身份、执行角色、节点类型与登记安排），候选携带事实变更、结构化行动结算结果与必要的后续世界事件；运行时校验、实际提交与发布分开记录。候选基于预裁决版本：裁决本身不得改变共同状态，校验关联裁决前捕获的版本，提交结果版本必须严格递增且等于 World 当前实际版本；后续事件身份与结算结果（与登记阶段、节点类型的兼容性）在事实提交前预检，提交之后只剩不会失败的发布步骤。未提交结果不得进入角色感知，提交错误不得留下半提交事实或发布成功结果。行动的登记阶段只随提交的结算结果变化，预计结束时刻到达本身不等于成功；未确认表示结果未知，不是已知客观终止。

本轮检查基于事件落地后的共同客观状态，不因角色完成先后改变事实前提。检查不开始行动、不提前提交停止效果、不预占对象、不登记事件。不同角色的候选独立检查通过，不保证未来互不影响，实际同刻事件仍须联合裁决。

角色是否继续愿意主动维持由角色决定。撤回维持后的身体运动、惯性、外力及其他效果由 World 判断（撤回节点同样走裁决、校验与提交）；不能因为被动效果仍在持续，就要求角色把它声明为主动行为。具体业务例子见核心文档「全量主动行为声明与被动影响」。

## 5. 本轮流程与生效边界

```text
时钟跳转到最近待处理事件的剧情时刻，同刻事件整批取出
    ↓
World 按已流逝剧情时间更新相关行动与被动过程的进展
    ↓
联合裁决：候选 → 运行时校验 → 原子提交 → 生成各角色输入
    ↓
角色 perceive → 完整主动行为声明 → World 检查
    ├─ 不通过：角色 rejected → 新完整声明 → 再检查
    └─ 通过：保存本轮候选，等待其他角色完成
    ↓
全部角色完成响应及必要的打回处理（屏障）
    ↓
翻译、校验时间安排（失败经 rejected 同周期重试）
    ↓
统一登记：完整准备并校验计划 → 撤回客观效果经 World 裁决提交 → 登记/撤回/队列调整统一生效
    ↓
完成本轮，允许推进下一剧情时刻
```

新的全量声明经检查、完成本轮统一登记后替换此前已接受的声明。打回候选不提前撤回原声明或清空队列。撤回主动维持的实际作用仍经 World 裁决与校验提交，不能直接拿响应集合覆盖客观状态。

保持原状也须返回维持集合；合法空集合表示角色从现在起没有要主动实施或维持的行为。字段缺失、解析失败、调用尚未完成或运行错误，不得被转换为空集合。

新行动的时间安排须满足开始时刻晚于当前时刻、结束晚于开始及组内共同非零交集；修改声明的安排须保留历史节点、结束晚于当前时刻。模型驱动的翻译器入口自行完成结构校验（非法 JSON、重复/未知字段、bool/浮点毫秒、身份或提交组关联不一致、多余安排都是运行错误），缺只读客观上下文同样是明确错误；时间业务约束仍由引擎的登记校验与打回执行。同角色并发翻译请求被拒绝，不同角色并行；录放按 translator-{角色} 作用域隔离。登记前校验把问题分为两类：结构不一致（翻译引用错误、缺安排、提交组关联错误、身份关联错误）属于运行错误，停止推进并保存现场；只有合法完整翻译中的时间安排不合业务约束才通过打回接口让角色重新决定（不重投原感知）。翻译器返回的类型错误或身份不一致同样属于运行错误。仅维持或空声明的轮次不调用翻译器，直接生成关联同一响应的空时间安排并参与统一登记。统一登记与队列变更（内部事件身份避让外部事件身份）完整准备并校验后再应用；修改与撤回的客观效果经 World 裁决提交后统一生效，之后只剩不会失败的发布步骤。

引擎不逐阶段调用 System1/2/3。全部角色完成思考、检查、打回、翻译和登记前，整个周期及所有模块的模型调用均保持剧情时间冻结。先通过检查的角色不能先行动；后段（翻译阶段）重试同样等待全部角色与翻译结束后统一生效。

登记与撤回在引擎侧先完整准备并校验再统一提交：失败不留下部分新行动已登记、旧行动已取消或队列已改变的混合状态。角色方法可能已更新私有状态，异常后不盲目重放整个调用，也不承诺整轮自动回滚；若 World 已完成当刻事实提交后角色异常，停止并保存现场，保留已提交事实与未生效候选。

## 6. 实现约定与验证

- 剧情时间和时长统一使用非负整数毫秒；配置中的秒在入口转换（`RunConfig.from_seconds`），不由场景自行解释 tick，也不使用浮点值比较事件时刻。毫秒是存储分辨率，不表示每毫秒调用模型；调度仍跳转到最近事件。
- 结构校验覆盖类型、身份、归属、引用、时间与状态一致性。语义检查不通过走打回流程；模型超时、格式错误及程序异常属于运行错误，停止推进、保存现场（可导出时刻、队列、行动记录、阶段、世界版本、候选与报错的 JSON 快照），不代替角色作出空集合决定。
- 角色方法可能已更新私有状态，异常后不能盲目重放整个调用，不承诺整轮自动回滚。
- 感知、响应、检查、打回、翻译和登记记录本轮、角色、响应及适用的行动身份，能够沿因果链查找。World 的候选、校验、提交与发布分别留痕；错误日志关联当前周期与阶段。Concordia 运行控制与真实界面步数据已随闭环交付：`StepController` 适配为运行门（许可在每个完整周期前的安全边界取得——初始化也是安全边界，不推进剧情时间、不计入墙钟预算，取消与停止释放等待线程），单周期报告转换为真实 `StepData` 广播（含同刻全部事件、登记记录与 World 客观诊断），运行结束以真实最终时刻与停止原因收尾；角色可见内容与观察者/诊断内容分开，不互相泄漏。
- 使用假模型验证：维持不重启；遗漏只撤回主动维持；空集合不抹除被动影响；打回候选不生效；修改不改历史；新组关联不丢失；旧反馈不误用；重试不推进剧情时间；全部角色完成前不越过屏障；返回顺序不决定冲突结果；暂停/继续/单步/停止与取消不影响已提交事实。
